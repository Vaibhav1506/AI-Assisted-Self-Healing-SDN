SELF HEALING SDN: DETECTOR COMPARISON AND VIVA NOTES

Purpose
Compare the three detection methods in this project: Random Forest only,
Random Forest + loss guard, and fixed thresholds. These notes describe the
current implementation and suitable uses within this laboratory testbed.

1. WHAT ALL THREE METHODS SHARE

Each method answers: "Is this path unhealthy?" The shared recovery policy
then decides whether to reroute. A detector decision alone is not a switch.

- Both paths are measured, including the standby path.
- The alternative must have links up and be assessed healthy.
- Soft degradation normally requires two consecutive unhealthy observations.
- A five-second hold-down after a switch limits further degradation switches.
- A hard link failure uses a separate link-state check and bypasses those
  confirmation and hold-down waits. A healthy alternative is still required.
- Successful rule installation commits the selected path. Recovery is checked
  separately using two healthy post-switch application probe windows while
  the injected fault persists.
- There is no automatic failback merely because the primary becomes healthy.

2. FIXED THRESHOLDS

How it works
The path is unhealthy if ANY of these conditions is true:
  measured probe loss >= 15%; RTT is missing; average RTT >= 40 ms;
  estimated link utilization >= 90%.
These are the fixed detector's rules. They are not all automatically applied
to the RF methods.

Advantages
- Easy to explain: a decision can be tied to a specific measurement limit.
- No training dataset or fitted model is needed.
- Limits can be chosen to reflect known operating requirements.
- Provides a transparent reference method for evaluating RF.

Disadvantages
- The same limits may not suit different networks, loads or normal delays.
- A normal but busy link can exceed 90% utilization and be marked unhealthy.
- A problem below every limit can be missed, even if the combined changes
  would matter to an application.
- Limits need review when operating conditions change.

When to use
- A small, understood network with clear acceptable limits.
- A classroom demonstration where the decision must be easy to explain.
- A comparison baseline when representative training data is unavailable.
- An explicit delay demonstration: the RTT rule directly checks 40 ms.

Example
At 95% utilization, fixed thresholds mark the path unhealthy even with low
loss and RTT. The policy still checks persistence and backup health before
rerouting. High utilization is a trigger here, not proof of poor service.

3. RANDOM FOREST ONLY

How it works
The fitted forest reads four features, in order: probe loss, average RTT,
RTT standard deviation, and utilization. A predicted degraded-class
probability >= 0.65 marks the path unhealthy. The demo loads the saved model;
it does not retrain it. 0.65 is a decision threshold, not 65% accuracy.

Advantages
- Can learn combinations of measurements rather than using only separate
  manually selected limits.
- Can represent nonlinear relationships between features and path health.
- Useful for examining what the fitted model itself recognizes or misses.

Disadvantages
- Depends on the quality and coverage of its original training examples.
- Can miss unfamiliar faults or misclassify healthy conditions.
- Harder to explain than a direct threshold comparison.
- Needs a compatible saved model and ML dependencies for inference.
- Validation accuracy does not guarantee performance at new capacities,
  topologies or fault conditions. Capacity changes do not retrain this model.

When to use
- Controlled experiments studying the model's own behavior.
- Evaluation on conditions represented by suitable measured training data,
  with independent tests before relying on the decisions.
- Ablation comparisons: remove the guard to measure what it contributes.

Project evidence
RF only missed the packet-loss fault in the presentation's saved comparison.
Its fitting report excludes dedicated packet-loss runs, although measured
loss remains an input feature. Some delay-only inputs are also known to be
missed. Do not assume this model detects every congestion or delay condition.

4. RANDOM FOREST + LOSS GUARD (DEFAULT)

How it works
Uses the same fitted forest, with an explicit override: measured probe loss
>= 15% marks the path unhealthy regardless of the forest's prediction.
Below 15%, the forest can still mark a path unhealthy using its features.
The guard does not add the fixed detector's 40 ms or 90% rules.

Advantages
- Retains RF's ability to respond to combinations of measurements.
- Adds a clear safeguard for substantial measured loss that RF might miss.
- The loss override is simple to explain and inspect.
- In the saved packet-loss comparison, it recovered when RF only did not.

Disadvantages
- Success can come from the guard, so it cannot all be credited to ML.
- The guard only explicitly protects against measured loss; it does not
  guarantee detection of delay or congestion without sufficient loss.
- Retains RF's model dependency and generalization limits.
- The 15% cutoff may need reconsideration for other operating requirements.
- Sampling variation can trigger the guard; the shared confirmation policy
  reduces reactions to isolated readings but cannot eliminate every error.

When to use
- The default demonstration of this project's combined ML and rule approach.
- Tests where an explicit loss safeguard is desired alongside RF decisions.
- Comparisons against RF only to demonstrate why a safeguard can matter.
- Any broader deployment would require representative testing and suitable
  limits; these lab runs do not establish production reliability.

Example
If measured loss is 20% and RF calls the path healthy, the guard overrides
that assessment. Two consecutive unhealthy observations can lead to a switch
if the backup is healthy and the hold-down permits it.

5. WHICH METHOD SHOULD I CHOOSE FOR THIS PROJECT?

Presentation / main demonstration: RF + loss guard, the existing default.
Explainable rules or a direct RTT limit: fixed thresholds.
Study the fitted model alone: RF only.
Measure the guard's contribution: compare RF only with RF + loss guard.
Assess relative performance: test all three with matching topology, scenario,
application load and capacity, and repeat trials before claiming superiority.

There is no universal winner. In the presentation's single-run packet-loss
comparison, guarded RF and fixed thresholds both recovered, while RF only
did not. Guarded RF confirmed recovery in 3.30 s and fixed thresholds in
3.35 s. That small difference does not prove guarded RF is consistently faster.

6. HOW THIS RELATES TO CONGESTION

At the default 10 Mbps capacity, the congestion scenario adds 12 Mbps of
background traffic while the main application offers 4 Mbps. New CLI and
dashboard runs scale background demand to 1.2 times the selected capacity.
Queueing and drops can increase RTT, loss and utilization.

- Fixed thresholds: any specified limit can mark the path unhealthy.
- RF only: the learned combination must produce a degraded score >= 0.65.
- RF + guard: RF can trigger, or measured loss >= 15% can trigger the guard.

For the two RF methods, 90% utilization alone is not a guaranteed trigger.
No method can reroute successfully during the fault without a healthy backup.

7. SHORT VIVA ANSWER

"Fixed thresholds are transparent and need no training, but their limits may
not suit every network. RF can learn combinations of measurements, but it can
miss conditions outside its training coverage. Guarded RF combines the same
model with an explicit 15% measured-loss rule. We use guarded RF as the default,
fixed rules as a clear reference, and RF alone to study the model and the
benefit of the guard. All three share the same recovery policy."
